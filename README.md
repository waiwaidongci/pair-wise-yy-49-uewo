# 高校课程标准映射与课程改革审阅平台

面向教研人员、课程负责人和院系审阅人的课程图谱平台，支持培养目标、毕业要求、课程单元、教学活动、考核任务映射，以及有向图检查、覆盖矩阵、拖拽连边、自动保存、批量审核和课程地图导出。

## 技术栈

SvelteKit + Skeleton UI + Svelte stores + SvelteKit Form Actions + TanStack Query + Zod + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev      # http://localhost:62049
npm run build    # 生产构建
npm test         # 引擎 + store 场景验证（35 组）
npm run check    # svelte-check 类型检查
```

## 核心工作流

- 在培养目标、毕业要求、课程、单元和考核之间建立有向映射。
- 自动检查前置关系、覆盖缺口、重复映射和不完整考核证据。
- 课程负责人提交修订，院系审阅人逐条退回、附议或要求补充证据。
- 比较版本覆盖变化，恢复草稿并导出专业课程地图。

## 修订批次（断网补录 / 回网合并）

课程负责人与院系审阅人共用同一份课程地图草稿。为避免「断网补录回传整包覆盖对方刚改的映射、证据和意见」，课程、连边、审阅意见与导出结果都以**条目**形式进入修订批次：

1. **建立批次即冻结**：创建批次时深拷贝冻结当时的节点、连边、审阅状态（`snapshot`），每条补录都带有冻结基线值 `baseValue` 与本地新值 `localValue`。
2. **断网照常补录**：离线期间拖拽节点、增删连边、补充证据、填写审阅意见、导出地图，全部写入本地批次队列（同一实体连续编辑折叠为一条，基线不变）。
3. **回网按条目三路合并**（`src/lib/batch/engine.ts`）：
   - 服务端未动 → 快进合并；
   - 服务端已独立应用相同结果 → 幂等跳过；
   - **双方都改过** → 保留双方现场，条目置「待确认」，由人工选择「采用本地 / 采用服务端 / 字段级合并」（审阅支持课程方新证据 + 审阅方意见并存）。
4. **结论失效重算且可追溯**：映射或证据一变，相关已附议/已退回结论自动归档（只追加的 `history`，含结论、意见、复核人、时间、依据指纹），结论置回待审阅并给出系统复核建议；审阅人重新附议/退回后新结论也进入历史，旧结论仍可查。
5. **失败保留现场、可接续重试**：合并在任一条目失败/中断时立即停止，已落库条目不回滚、不重复，后续条目保持排队；修复后从断点重试，也可放弃单条后继续。
6. **导出随批次回传**：导出 JSON 含批次号、基线版本与校验和，作为 `export` 条目排队，回网后幂等登记（同校验和不重复）。
7. **旧草稿兼容升级**：没有批次号的 v1 本地草稿（`curriculum-map-draft-v1`）首次打开时自动生成「旧草稿兼容升级」批次，差异逐条转入并自动合并，随后迁移到 v2 存储（`curriculum-revision-batches-v2`）。

批次控制台位于 `/batches`，支持模拟断网/回网、模拟对端在线修改（制造双方冲突）、中断演练与冲突裁决。

### 代码结构

- `src/lib/batch/types.ts`：批次、条目、冻结快照、合并报告、审阅历史等领域模型。
- `src/lib/batch/engine.ts`：纯函数引擎——冻结、三路分类、合并、冲突裁决、结论归档重算、失败重试。
- `src/lib/stores.ts`：Svelte store，持久化、旧草稿升级、服务端权威状态 + 本地补录叠加的工作视图，以及各页面调用的编辑/导出 API。
- `scripts/engine-check.ts`、`scripts/store-check.ts`：引擎语义与端到端工作流场景验证。
